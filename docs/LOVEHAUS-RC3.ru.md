# LOVEHAUS · 1.2.0-rc3

## Обновление и аварийный возврат

Эта версия поддерживает две проверяемые исходные конфигурации HOME: штатный Leanback и зарегистрированный HomeChoice. Обновление выполняется с помощью install -r. Существующее состояние enabled штатного пакета, хранилище Panel, ключ сопряжения, выбранные сущности, подписи плиток и порядок HDMI сохраняются. Форматы Android SharedPreferences и прежних параметров HA совместимы, добавочные поля имеют значения по умолчанию.

1. На Windows распакуйте комплект. В папке windows укажите адрес ADB и запустите диагностику.
2. Проверьте серийный адрес, user 0, прошивку, фактический HOME, состояние Leanback и активную карту HDMI. Запустите обновление. Оба старых APK и доступное через ADB системное состояние сохраняются в %LOCALAPPDATA%\BraviaHome. Скопируйте путь каталога из вывода. Материалы предназначены для локального хранения. Резервная копия содержит сведения об устройстве. Android Keystore и закрытые SharedPreferences недоступны обычному ADB.
3. При обрыве Wi-Fi заново запустите update.ps1. Скрипт проверяет оба установленных пакета и пропускает уже обновлённый APK. Используется проверенная пара Home 17 / Panel 5. При нестандартной подписи установка прекращается.
4. Для возврата на штатный экран запустите restore.ps1 с исходным каталогом. Если Leanback отключён, скрипт отдельно запросит ENABLE LEANBACK. После возврата нажмите физическую Home, затем проверьте её после обычной перезагрузки. Скрипт восстанавливает интерфейс. APK с меньшим versionCode невозможно штатно установить поверх новой версии с гарантией сохранения данных.

```powershell
$env:BRAVIA_TV = Read-Host 'IPv4 телевизора с портом 5555'
.\diagnose.ps1
.\update.ps1
# Отдельная операция по решению владельца
.\restore.ps1 -Backup (Read-Host 'Каталог резервной копии')
```

При сбое пользовательского HOME можно вернуть **штатный экран** непосредственно из авторизованного ADB. Первая команда меняет состояние пакета и нужна только при отключённом Leanback.

```powershell
$adb = "$env:USERPROFILE\Desktop\platform-tools\adb.exe"
& $adb -s $env:BRAVIA_TV shell pm enable --user 0 com.google.android.leanbacklauncher
& $adb -s $env:BRAVIA_TV shell am start -n com.google.android.leanbacklauncher/.MainActivity
```

Сохранённый inputs.txt содержит исходный dumpsys. Установщик принимает только активные соответствия и не фиксирует назначение номеров HW в коде. При аппаратной приёмке проверьте картинку и звук с каждого входа.

## Карточки и пульт

После появления версии в Marketplace обновите существующую интеграцию и перезапустите HA. Для стендовой проверки ветки используйте каталог custom_components из этой версии. В параметрах уже сопряжённого ТВ откройте **Конструктор карточек**. Выберите «+» или имеющуюся карточку. Выберите шаблон, сущность, компактный экран, название, символ, порядок и действие. Для просмотра оставьте действие «—». Меньший номер порядка означает более высокий приоритет. Шаблон link открывает экран или один из четырёх HDMI. Карточки можно скрывать и удалять.

Для уборки заранее создайте и проверьте script в HA. В карточке выберите шаблон script, конкретную сущность, экран «Сценарии» и операцию turn_on. Оставьте подтверждение включённым. Телевизор передаёт ключ карточки. Интеграция заново проверяет запись телевизора, наличие цели, доступность и соответствие разрешённой операции. В сценариях и сценах HA могут быть действия над несколькими устройствами — учитывайте их при выдаче разрешения.

В **Главный экран и пульт** выберите действие «Мой дом» и назначения четырёх цветов. Без назначения кнопка сохраняет обычное поведение. «Свет» показывает выбранные лампы, OK переключает доступную лампу с выданным правом. Обновление значения приходит от HA. Для обычных переключателей сохраняется подтверждение. Локальное редактирование HDMI, приложений и сводок находится в «Вид экрана».

Шаблоны устройств поддерживают явный список активных состояний. Для сушилки выбирайте сущность программы или датчик работы. Розетка с питанием сама по себе не означает работающий цикл. «Недоступные» отделены от предупреждений. Для конкретной карточки можно включить предупреждение о недоступности и задержку. Политика сигналов безопасности задаётся отдельно.

Бытовые события выключены по умолчанию. Включите их в параметрах ТВ или его switch Live Activities. Отметьте карточки-источники, состояние события, время отображения, порядок и при наличии датчик ETA (duration / timestamp). Выключение очищает строку на Home и сохраняется в HA. Остальные приложения уведомлений от LOVEHAUS не получают.

## Диагностика и область действия клавиш

OK на индикаторе сети показывает интерфейс, локальные адреса, RSSI для Wi-Fi при наличии, адрес HA, последнее успешное получение данных и статус SSE. Успешная авторизация подтверждается живым потоком. Кнопка повтора заново открывает подписку. При остановленном HA сеть может сохранять Wi-Fi 4/4 или Ethernet. Проблемы транспорта видны отдельно от проблем устройств.

В диалоге сети выберите «Пульт». Нажмите и отпустите по очереди четыре цвета и запишите keyCode, action, repeatCount и source. Проверяйте также нажатие и удержание внутри Home и Panel. Стандартные Android KEYCODE_PROG_RED..BLUE обрабатываются только при назначении, один раз на первое нажатие. Передача этих событий физической прошивкой требует проверки владельцем.

Обычная Activity получает клавиши, пока имеет фокус. Разрешение SYSTEM_ALERT_WINDOW даёт возможность рисовать окно и само по себе не даёт глобальных клавиш. AccessibilityService с canRequestFilterKeyEvents требует ручного включения, конкурирует за фильтрацию и не гарантирует доставку перехваченных Sony событий. Отрисовка поверх HDMI зависит также от системных окон и видеоплоскости прошивки. Для RC3 выбран режим внутри LOVEHAUS. Разрешения overlay и AccessibilityService в комплект не входят. ACTION MENU, HOME, POWER, INPUT, громкость и Netflix не переназначаются.
